# ADR 0001. Стек прототипа

Статус: принято для прототипа (M0–M3), пересмотреть после ворот G1.

## Контекст

Спецификация (`docs/spec/03-architecture.md`, раздел 2) выбрала Vite + Preact + Vitest + ESLint. В среде, где работает ИИ-агент, реестр npm недоступен: установить можно только пакеты, которые уже есть в образе (esbuild, TypeScript, tsx, Zod, yaml, Playwright, Prettier). Без установки зависимостей агент не может проверять сборку, типы и тесты — а это обязательное условие каждой вехи.

## Решение

| Слой | В спецификации | В прототипе | Почему так можно |
| --- | --- | --- | --- |
| Сборщик | Vite | **esbuild** напрямую (`scripts/build.ts`, `scripts/dev.ts`) | Vite сам использует esbuild; сборка явная и короткая |
| UI | Preact | **TypeScript без фреймворка**: маленькие функции-компоненты, создающие DOM (`src/ui/dom.ts`), и точечное обновление | Ядро не зависит от UI; интерфейс прототипа небольшой; ноль runtime-зависимостей, минимальный размер |
| Тесты | Vitest | **node:test** + tsx | Встроен в Node 22, тот же синтаксис describe/it |
| Линт | ESLint + typescript-eslint | **tsc strict** + **Prettier** + свой `scripts/lint.ts` (границы слоёв, чистота ядра, кириллица в коде) | Правила проекта проверяются явно; типовые ошибки ловит строгий tsc |
| e2e | Playwright | Playwright (без изменений) | — |
| Контент | YAML + Zod | YAML + Zod (без изменений) | — |

Версии зависимостей закреплены точно в `package.json`. `package-lock.json` пока нет: его нужно сгенерировать один раз там, где есть доступ к реестру (`npm install` и коммит lock-файла), после чего CI перейти на `npm ci`.

## Последствия

- Сайт не тянет ни одной runtime-зависимости: весь JS — наш код.
- Если после G1 интерфейс начнёт усложняться (уроки, тесты, коллекция), переход на Preact затрагивает только `src/ui/` и `src/app/`: ядро, эффекты и контент не меняются.
- Отклонение от спецификации нужно подтвердить автору (вопрос в отчёте по вехе M0).
